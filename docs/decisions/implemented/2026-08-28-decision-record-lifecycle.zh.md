# 决策记录用三态目录落地，不做双语三元组，也不先上格式校验脚本

## 决定了什么

在本仓库用 `docs/decisions/{proposed|implemented|archived}/` 三个文件夹表达决策记录的状态，状态变化即移动文件；不引入 DSH 原始机制里的中英双语三元组，也暂不写格式校验脚本。归档判断靠人读、靠"未来是否还需要它做决定"，不靠字数或时间。

## 背景

[restraint-engineering-report.md](../../restraint-engineering-report.md) 的 M1 描述了 DSH 仓库的决策记录机制：状态编码在路径里、归档后整体冻结、归档判断靠校准过的人类判断而非自动规则。报告的 RSP 映射表建议"先从轻量版开始"，本仓库目前是一个空仓库，没有既有的 PR 流程或团队规模去支撑一套带格式校验脚本的完整机制。

## 考虑过的替代方案

- **照抄 DSH 的双语三元组结构** — 对单人/小范围试点没有必要，双语维护成本和当前规模不匹配。
- **先写格式校验脚本再开始用** — 报告本身在"提醒"一节里明确说"先做零成本的，再碰门禁"；脚本没有使用样本时无从设计，容易写出不合用的规则。
- **不设三个文件夹，只在文件内容里标注状态字段** — 状态字段可以被悄悄改掉而不留痕，路径迁移比字段更难被绕过，也更符合 M1 本身的设计意图。

## 为什么这样选

三态目录零工具成本，今天就能用；把归档判断留给人，避免报告"哪些不要照抄"一节里点名的风险——自动化的字数/时间归档规则会砍掉真正有价值的记录。等这套约定被真的持续使用几周后，再考虑要不要补一个格式校验脚本（对应报告里的阶段三）。
